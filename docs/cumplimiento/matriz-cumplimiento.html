Revisión del 26 de noviembre de 2026 sobre el código de GitHub: backend en la rama enggel (commit 5c49b50) y frontend en la rama javier (commit 9617b59). Los requisitos se citan del enunciado (docs/reto/IA_RETO_GRUPAL_PROPUESTA_DE_SERVICIOS_enunciado_.pdf); en los textos con caracteres dañados por la fuente del PDF se restituyen las letras (p. ej. «En recepción»). Rutas relativas a la raíz del repositorio.
Cómo leer los estados. CUMPLE implementado y verificado en el código, con prueba o ejecución. PARCIAL implementado con brechas, o implementado en cada rama por separado pero sin funcionar todavía de extremo a extremo. FALTA no implementado. N/A no corresponde a esa capa. La columna Global es el estado de la solución integrada.
Hallazgo principal: la integración frontend ↔ backend está pendiente. El frontend llama a rutas bajo /api con nombres y campos propios (frontend/src/api/http.ts: PATCH /projects/{id}/estado, /evaluations/{id}/revisiones, /currency/bcv, /audit, /users…) y el backend publica /api/v1 con otras (POST /projects/{id}/status, /evaluations/{id}/reviews, /finance/bcv-rate, /audit-logs, /auth/users…). Por defecto el frontend usa datos simulados (VITE_USE_MOCK=true, frontend/src/api/mock/). Por eso todos los requisitos de interfaz y plataforma (D y E) quedan en PARCIAL globalmente aunque cada capa los tenga. Se sigue en los issues #3 y #4.

Verificaciones ejecutadas

Sobre una fusión local temporal de enggel + javier (sin publicar), con Python 3.14, Node 22 y Tesseract instalados:

  • cd backend && pip install -e ".[dev]" && pytest: 9 pruebas, 9 correctas (3 de cifrado, 5 de ingesta y auditoría, 1 de plataforma completa con roles). ruff check app tests: sin hallazgos.
  • cd frontend && npm ci && npm run build (tsc --noEmit + vite build): correcto. El frontend no tiene pruebas automatizadas.
  • Modo lote sin clave de IA ni búsqueda web (LLM_PROVIDER=heuristic python -m app.cli.batch --lote ../docs/reto --no-web-search --bcv-rate 52.5): 10 propuestas procesadas en 13 s, 5 válidas y 5 descartadas, salida.json validado por el propio programa. El campo repositorio salió como la ruta local del clon, porque se toma del remoto origin si no se define HACKATHON_REPO_PATH.
  • No se probó con clave real de Gemini u OpenAI, con búsqueda web activa ni con TLS activado.
